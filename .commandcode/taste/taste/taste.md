# Taste
- Specifies an allowed stack for projects and expects it to be respected strictly ("techstack should only include node js, express, html, css, tailwind, vanilla js, react, postgresql") — prefers plain, dependency-light JS/Node/Postgres work over additional frameworks or libraries. Confidence: 0.6
- Criticises generic "AI-generated"-looking UI, specifically indigo/violet gradients and default palette choices, and asks for the colour scheme to be changed away from them. Confidence: 0.55
- Expects interactive UI to update in place without a manual page refresh — flags "have to refresh the page to see the changes" as a defect, so counts, scores and list ordering should react immediately (optimistic/live updates). Confidence: 0.5
- Prefers a calm, low-density UI over feature-rich pages: reacts against "information overload" and wants content to be revealed gradually (progressive disclosure — collapsed sections, quiet single-line summaries instead of stat-card grids, dropdowns instead of chip rows) rather than everything shown at once. Confidence: 0.6
- Prefers speculative or uncertain features be built on a cheap rollback point ("ya lets do that and if we don't like lets just rollback") — expects changes to be easily revertible rather than irreversible. Confidence: 0.55
- Prefers applied, real-world-impact project ideas (e.g. agriculture, market access for small enterprises, livelihood/accessibility apps) over pure "software-engineering showcase" projects like distributed systems, infrastructure, or dev tooling — pushed back when a shortlist skewed toward the latter. Confidence: 0.6
